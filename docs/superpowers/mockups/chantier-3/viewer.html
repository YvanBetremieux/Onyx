Trois bugs qui rendaient le pipeline silencieux

Une session de debug déclenchée par un enregistrement qui semblait ne rien produire. Diagnostic, correctifs, et confirmation que le pipeline tournait bien — juste sans le dire.

Points clés

  • Le pipeline n'était pas hangé. La compilation Core ML de whisper large-v3 prend 4 à 5 minutes au premier run à froid. Le sample CPU est trompeur : le Neural Engine bosse en dehors du profil user-space.
  • L'UI n'affichait jamais l'état "transcribing". uiState = .transcribing était écrasé par uiState = .idle dans la foulée, dans le même bloc toggleRecording.
  • Les erreurs du pipeline étaient avalées. Fire-and-forget Task.detached avec catch { _ = error } — aucune remontée vers l'UI ou vers l'utilisateur.

Décisions

  • Ajout d'un callback onPipelineFinished sur RecorderSession pour surfacer succès et échec.
  • Timeout de 8 min sur WhisperKit(cfg) via withThrowingTaskGroup. Assez pour la compil, assez court pour catcher un vrai hang réseau.
  • L'UI reste bloquée en .transcribing jusqu'à la fin réelle du pipeline. Icône jaune ⌛ + label maintenus.

Actions

Ajouter un panneau "état pipeline" dans le menu bar (étape courante, ETA, bouton annuler).
